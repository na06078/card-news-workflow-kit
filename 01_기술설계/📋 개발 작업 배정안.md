# 카드뉴스 실습 — 개발 작업 배정안

> **카드 초안만 작성, 사용자 설계 승인 대기.** 아래 `S0/F1/B1/G1/R1/W1/I1/I2/Q1/J1/J2`는 문서 안의 초안 참조이며 실제 Kanban ID가 아니에요. 생성·연결·차단 해제/담당 실행은 **default가 사용자 승인 후** 수행해요. 모델 override 선택 없음.

## 1. 사용자용 순서·승인

공유 계약은 홀과 주방이 같은 주문서를 쓰는 약속이에요. 그 양식과 공용 파일만 먼저 맞춘 뒤 화면·저장·AI 연결·출력을 **서로 기다리지 않고** 개발하고, 연결할 수 있는 부분부터 점검해요.

| 순서 | 초안 | 담당 | 독립/연결 조건 |
|---|---|---|---|
| 공통 준비 | S0 | backend-dev | 공용 타입/설정 단독 소유, 설치/경로 승인 이후 |
| 최대 병렬 A | F1 화면 / B1 저장·HTTP / G1 SDK·agy / R1 렌더 | frontend-dev / backend-dev | S0 후 즉시 독립. provider 막혀도 UI/DB/렌더 오프라인 개발 가능 |
| 작업 연결 | W1 worker | backend-dev | S0+B1 persistence port 준비, provider/render는 인터페이스 기반 test double로 먼저 진행 |
| 상시 중간 점검 | I1 | backend-dev(통합 책임) | S0 후 준비된 경계마다 점검, 미완성 영역은 pending; 전부 완료 대기 금지 |
| 실제 전체 검증·제출 준비 | I2 | backend-dev(통합 책임) | F1/B1/G1/R1/W1 완료+실행 권한; I1 checkpoint 확인 |
| 독립 비판 | Q1 | critic | 완성된 해당 결과/실로그 읽기 전용 |
| 비판 채택 판단 | J1 | reviewer | Q1 후 채택/거절/보류, 고치지 않음 |
| 수정·최종 검토 | 소유자 수정 초안(필요 시 default) → J2 | 해당 기존 소유자 / reviewer | 채택 수정 재검증 후 최종 검토, 사용자 최종 승인 대체 아님 |

**DAG(제안):** 승인/경로·실행권한→S0→{F1,B1,G1,R1,I1}; B1→W1; {F1,B1,G1,R1,W1,I1}→I2→Q1→J1→(필요한 소유자 수정·재검증)→J2. I1은 모든 생산 카드의 자식으로 묶지 않고 S0만 선행으로 둬서 준비된 연결부터 실행해요. 개별 checkpoint 증거가 오면 default가 재개/후속 검증 카드로 운영하며, 준비되지 않은 경계 때문에 생산 카드를 막는 역방향 의존은 만들지 않아요. 무한 polling로 worker를 점유하지 않고 현재 가능한 checkpoint를 검증한 뒤 남은 의존을 명시해요. I2는 최종 전체 검증이라 전체 생산 완료를 기다리는 것이 맞아요.

- **미승인 인간 게이트:** 상세 설계 결과; 구현 위치/데이터 경로/의존 설치; 브라우저·localhost 실행; 본인 구독 활성 경로/추가과금 없는 실호출; agy 권한/실이미지; Git/제출; 비판 방식.
- 비판 방식: **[사용자 결정]**. 의미 단위별이면 I1 checkpoint 결과마다 read-only critic→reviewer 판단을 붙이는 초안, 결과물 전체면 I2 후 Q1 1개. 어느 쪽도 UI와 백엔드의 개발 진도를 lockstep으로 묶지 않아요.
- 같은 backend-dev 프로필을 여러 파일 경계에 사용할 수 있으나 실제 동시 실행 가능 수는 default가 실제 배정 때 확인. 새 renderer 프로필/봇 생성 없음.
