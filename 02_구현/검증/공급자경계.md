# G1 공급자 경계 — 구현·오프라인 증거와 실호출 차단

## 결론
- 아이펠 노드 실습 `02_구현`의 **공급자 연결 코드/오프라인 검증 단계**입니다. 실제 본인 구독 인증·검색·agy 생성은 **UNVERIFIED / 이번 승인에서 실행 금지**입니다. 앱 전체 ACCEPTANCE 완료가 아닙니다.
- Claude Agent SDK **0.3.309**, 패키지의 `claudeCodeVersion` **2.1.309**, 설치된 win32-x64 native 패키지 **0.3.309**를 안전한 package/type/source 파일로 확인했습니다. 바이너리·로그인·status·query·warmup·auth-refresh를 실행하지 않았습니다.
- 정상 `createClaudeAdapter`는 같은 자식의 인증/실효 설정/추가과금 없음이 입증되지 않아 **SDK import 전 AUTH_MODE_UNKNOWN**입니다. 정상 `createAgyAdapter`도 설치 버전·최소 이미지 권한 미검증으로 **spawn 전 TOOL_PERMISSION_DENIED**입니다. 호출자가 approvalReference/크레딧 확인 객체를 넣어도 열리지 않습니다.
- 실제 `sdk.query` 동적 import/호출과 `spawn(executable,argv,{shell:false})` 코드는 있습니다. 현재 승인에서 안전하게 도달 가능한 실호출 경로는 의도적으로 없습니다. 성공 attestation/가짜 auth 플래그/다른 엔진 fallback을 만들지 않았습니다.

## 수정 범위와 연결 포트
기준: `src/shared/포트.ts` 및 재수출된 CN-1 DTO/validator. 공유 파일/설정/package/lock/bootstrap·frontend/backend/render/worker·원본 키트/설계/현재상태는 수정하지 않았습니다. Git 명령·설치·다른 프로필/스킬 수정 없음.

### W1/B1 연결 책임
- W1이 run별 ProviderBridge를 주입합니다. progress/openQuestion/publishResult/publishError/saveSession은 **bridge가 영속화한 뒤 반환한 이벤트만 yield**합니다. G1은 seq를 만들거나 DB/raw SQL을 사용하지 않습니다. W1이 같은 이벤트를 다시 append하면 안 됩니다.
- 질문 답변은 `bridge.waitForAnswer`의 DB polling/현재 질문 버전 검사가 소유합니다. `answer()`는 메모리상 현재 대기 질문의 project/run/attempt/ID/version 확인만 하고 새 추론을 시작하지 않습니다. 전달 완료 mark/fence 갱신은 W1/B1 책임입니다.
- 명시 session ID와 cwd/project owner를 검사합니다. 같은 adapter에서 관찰한 세션만 명시 resume 가능; 새로운 adapter의 미확인 재시작 세션은 `SESSION_RECOVERY_UNVERIFIED`. 최신 세션/continue 탐색 없음. callback Promise는 프로세스 종료를 넘겨 살아남지 않습니다.
- consumer 종료/AbortSignal/cancel/dispose는 SDK AbortController와 query.close에 연결됩니다. 실제 SDK spawn을 사용할 미래 경로는 자식 exit 대기/10초 cleanup 오류 경계를 가집니다. agy는 async FS 준비 전에 run 슬롯을 예약하고 해당 run handle에만 cancel을 전달합니다. 실제 Windows SDK/agy의 손자 프로세스까지 종료되는지는 **미검증**입니다.
- 생성 이미지 반환은 DB commit이 아닙니다. W1/B1은 VerifiedAsset을 현재 fence/attempt 아래 원자 등록하고, 렌더와 최종 승인을 별도로 검사해야 합니다.

### 구독 preflight 판정
1. 현재 배치에서 query 자체가 금지이므로 빈 AsyncIterable을 넣은 초기화조차 하지 않습니다. 안전한 초기화 방법이 전혀 없다고 단정하는 것도 아닙니다. 공식 메서드는 있지만 **같은 자식에서 무추론 초기화/active subscription의 양성 조합/실효 설정/크레딧 비활성화까지 안전하게 확인했다는 증거가 없습니다**.
2. `inspectAccountMetadata`는 non-firstParty, API key/Console/helper 경로를 거부합니다. 필드 누락, apiKeySource='none', tokenSource에 OAuth라는 문자열, subscriptionType 문자열, cost0 또는 응답 성공으로 인증을 통과시키지 않습니다.
3. caller의 `usageCreditsDisabled`는 비밀 없는 확인 근거의 입력 자리일 뿐 인증 attestation이 아닙니다. 현재 그 값이 있어도 AUTH_MODE_UNKNOWN입니다. SDK의 cost/usage/maxBudgetUsd는 청구원 증명이 아닙니다.
4. 새 프로세스/인증 갱신/설정 변경에서 다시 확인해야 하며 SDK `auth_status`가 관찰되면 불명으로 중단합니다. usage credits가 켜짐을 알리는 rate-limit 필드가 true면 중단하지만, false/누락이 사전 과금 차단 증거가 되는 것은 아닙니다.
5. API/Console/cloud/CLI/타 제공자/다른 모델로 fallback하지 않습니다. 모델 지정·continue·fallbackModel 옵션도 추가하지 않았고 PreModelSwitch hook은 deny입니다. 관리형 설정의 효과까지 덮어쓴다는 보장은 없습니다.

### 자식 환경·설정 한계
- 전달 allowlist(이름만): PATH, SystemRoot, WINDIR, ComSpec, PATHEXT, USERPROFILE, HOME, APPDATA, LOCALAPPDATA, TEMP, TMP. host env는 수정하지 않고 값은 로그에 출력하지 않습니다. 프로필/credential/token/config-dir/proxy/provider/클라우드/CA/NODE_OPTIONS 등은 전달하지 않습니다. 기존 계정은 기본 사용자 위치를 유지하며 credential 파일/토큰 복사·새 로그인 위치 생성 없음.
- 설치 SDK가 실제 추가하는 비인증 marker만 최종 spawn env에 허용: `CLAUDE_CODE_ENTRYPOINT=sdk-ts`, `CLAUDE_AGENT_SDK_VERSION=0.3.309`, `CLAUDE_CODE_SDK_READS_SESSION_STATE=1`, `CLAUDE_CODE_SDK_READS_STARTUP_MARKS=1`. 정적 sdk.mjs 구성문으로 확인했습니다. 임의 새 값·OAuth refresh hook·추적 context 추가값은 거절합니다.
- `settingSources:[]`, `strictMcpConfig:true`, `mcpServers:{}`, `plugins:[]`, `settings.autoMemoryEnabled:false`, `settings.disableAllHooks:true`만 문서화된 옵션으로 전달합니다. 설치 settings 설명의 disableAllHooks는 settings/plugin hook·statusLine 억제이며 SDK callback까지 검증됐다는 뜻이 아닙니다.
- **managed policy/global .claude.json/서버 설정/도우미가 완전히 무력화됐다고 주장하지 않습니다.** 실제 초기화의 hooks 적용 여부, 자동 보조 호출/모델 선택, MCP/정책의 실효 상태는 live gate에서 관찰·검토해야 합니다. 불명인 현재는 프롬프트를 열지 않습니다.

## 검색·편집·질문 프로토콜
- research tools는 WebSearch/WebFetch만, editorial/revision은 위 둘과 AskUserQuestion만 제공합니다. tools 목록 자체를 제한하고 PreToolUse/canUseTool에서 임의 Bash/Write/Read/Edit/Agent/MCP를 거절합니다. allowedTools만으로 제한한다고 주장하지 않습니다.
- SDK init의 허용 밖 도구/MCP/permission mode 변경·검색 도구 누락은 중단합니다. editorial WebFetch는 snapshot의 **선택 후보 source URL**로 제한합니다. 새 1차 URL은 research에서 확보하여 snapshot에 포함해야 합니다.
- URL 검사는 공유 PublicUrlSchema의 공개 HTTPS **구문 검사**입니다. SDK 내장 WebFetch의 DNS/private IP/redirect 전체 egress 차단은 오프라인에서 입증하지 않았습니다. 이 상태로 실호출을 열어서는 안 됩니다.
- 조사 anchor/from/to/days의 일관성과 7일/승인된30일 간격을 검사합니다. 사건일이 기간 밖이면 후보에서 제외, 게시일이 최신이라는 이유로 오래된 사건을 살리지 않습니다. 미래 날짜/참조 누락/버전 불일치/잘못된 결과는 실패합니다.
- 동일 eventKey 후보는 source IDs를 묶고 source.candidateId를 대표 후보로 맞춥니다. 사건일 미확인은 불확실성으로 표시하고 ‘기간 안 사건일 확인 후보’ 수에 세지 않습니다. 부족 시 실제 수와 30일 선택 필요를 shortageReason으로 반환하며 앱이 사용자 선택을 받아야 합니다. 날짜는 DTO의 일 단위 정밀도이며 실제 시각 대조/의미적 사건 중복 판정은 미검증입니다.
- editorial은 선택 범위만 source/claim/card에 허용. verified에는 접근된 원문·evidence 필요, 1차 자료가 없으면 한계가 필요합니다. publisher_claim/uncertain/conflicting와 announced/released/unknown 구별을 보존합니다. **본문의 사실·게시자 정체·성능 독립 검증을 구조 검사만으로 보증하지 않습니다.** 고정된 출력 크기도 임의 변경할 수 없습니다.
- SDK 결과는 subtype='success', is_error=false, 세션 일치, permission_denials 없음, structured_output의 공유 구조+의미 검증을 모두 통과한 뒤 bridge.publishResult에 전달합니다. assistant text/exit/‘완료’ 문구로 성공하지 않습니다.
- AskUserQuestion 원 question 문자열 중복·같은 label 중복·범위 오류를 거부합니다. DB question/mapping 저장→답변 대기→모든 item/option/single-select 재검증→`{behavior:'allow',updatedInput:{questions:원배열,answers:Record<원질문,string>}}`. 다중선택은 label을 `, `로 연결, 자유입력 공백/개행 원문 보존. 추천은 사용자 답변이 아닙니다.

## agy와 실제 파일 경계
- 공식 headless JSON envelope를 독립 파싱: conversation_id/status/response/duration_seconds/num_turns/usage. SDK session_id/result 형식으로 해석하지 않습니다. 문서에 없는 고정 assetPath/toolVersion JSON 필드를 발명하지 않았습니다.
- 실제 경계 코드는 절대 executable과 `['-p',자연어,'--output-format','json']`, `cwd=attemptDir`, sanitized env, `shell:false`. `agy image generate`, 권한 전면 skip, 셸 문자열 연결, 다른 모델 override 없음.
- 현재 실제 CLI 버전/최소 permissions.allow 규칙/계정/내장 generate_image 가용성은 **UNVERIFIED/provisional**입니다. 따라서 production 게이트는 닫혀 있고, fake가 검증한 argv를 실제 실행 성공으로 보고하지 않습니다.
- 예상 파일은 attemptDir 안 `image.png` 하나. 기존 파일이 있으면 새 시도 성공으로 재사용하지 않습니다. 응답 서술에 PNG 경로가 있으면 예상 파일과 대조하며, 다른 경로/UNC/ADS/드라이브 탈출/불명 envelope/soft permission deny는 성공이 아닙니다.
- attemptDir lstat+realpath, 파일 regular/no symlink/no hardlink, containment, 50MiB 이하, PNG signature/IHDR, 1..4096 dimensions, **pngjs 실제 CRC decode**, fd stat/realpath 재확인, 실제 byte/hash를 검사합니다. 생성 원본은 최종 카드 크기와 달라도 됩니다. 실제 파일 없는 SUCCESS/exit0은 거부합니다.
- TOCTOU 전체를 OS 샌드박스로 해결한 것은 아닙니다. 악의적인 외부 프로세스가 계속 파일/상위 디렉터리를 바꾸는 상황과 Windows 하위 작업 트리 취소는 별도 검증 대상입니다. W1/B1도 등록/사용 시 hash와 현재 경계를 재검사해야 합니다.
- provenance는 illustrative=true, 도구/생성시각/실제 전달 prompt/conversation ID/이용조건 미확인(false)을 보존합니다. 오프라인 fake의 toolVersion은 **OFFLINE_TEST_FAKE**로 고정, 실제 생성 provenance라고 부르지 않습니다. 생성 그림을 저작권 없음/실제 사건 사진으로 표시하지 않습니다.

## 실제 실행·검증 기록
실행 위치는 APP, Node `./.도구/node-v24.22.1-win-x64/node.exe`입니다. 재설치하지 않았습니다. 정확한 argv/cwd/exit/log/time은 `실행데이터/G1/실행결과.json`에 있습니다. 재실행 helper는 `실행데이터/G1/최종검사.mjs`이며 승인된 오프라인 명령만 실행합니다.

- `npm run test:providers:offline -- --configLoader runner --reporter=default --reporter=json --outputFile=실행데이터/G1/vitest결과.json`: **6개 파일, 57개 통과 / 파일 symlink 1개 SKIP(전체58), 실패0**, exit0. runner loader로 공용 bundle temp 사용을 줄이고 Vitest cache=false, cache/TEMP는 G1 namespace입니다.
- 전용 node `node_modules/typescript/bin/tsc --noEmit -p 실행데이터/G1/tsconfig.g1.json`: provider + provider tests의 focused typecheck, exit0.
- `npm run typecheck`: 프로젝트 전체 noEmit, exit0(실행 시점).
- `npm run test:shared -- --configLoader runner`: 공유 회귀 29개 통과, exit0.
- **파일 symlink 1건 SKIP:** Windows EPERM으로 실제 파일 symlink를 만들 수 없었습니다. 기존 테스트가 생성 실패까지 성공으로 셀 수 있음을 자체 점검해 수정했습니다. 권한 상승/정책 변경 없이 명시 SKIP으로 남겼고 실제 junction 거절은 통과했습니다.
- `구독실검증.test.ts`, `agy실검증.test.ts`는 import/실행 없는 명시 skip이며 기본 suite에서 제외됩니다. 기존 test:live:* script도 LIVE_CALLS_FORBIDDEN exit2 차단용입니다. 환경변수 하나로 live를 켜지 않습니다.
- no-live 감사는 SDK module factory/query와 node child_process.spawn을 스파이로 막고 정상 두 factory에 위조 승인까지 주입하여 **SDK import/query/공급자 spawn 각각0**을 확인합니다. 나머지 테스트도 명시 DI fake SDK/subprocess만 사용합니다. 합성 PNG와 example.org 모의 데이터는 실제 연구·생성 증거가 아닙니다. 테스트 runner의 Node 자식 실행을 공급자 실행0과 혼동하지 않습니다.
- 이 작업에서 실제 DB/localhost/브라우저/모델/검색/agy 프로세스를 실행하지 않았습니다. 공개 문서 HTTPS 읽기와 안전한 설치 패키지 읽기만 했습니다. full build는 I2 소유이므로 실행하지 않았습니다.

### 실제 실패와 수정(모두 로컬)
- TDD RED는 신규 모듈 부재부터 시작했습니다. 단계별 RED/GREEN 로그를 G1 아래 보존했습니다.
- 초기 SDK cleanup에서 close 두 번을 재현→한 번만 소비하도록 handle 해제; 초기 typecheck의 never 함수 narrowing/테스트 each 배열/ES lib 문제→소유 파일에서 수정.
- editorial fixture가 기존 storyboard version을 재사용해 검증 실패→공유 계약대로 version2 fixture로 정정(검증을 완화하지 않음).
- 타입검사 중 B1의 아직 작성 중인 앱 import 누락을 한 차례 관찰했습니다(`타입-중간.log`); 해당 파일을 수정하지 않았고 최종 전체 typecheck는 통과했습니다.
- agy 동시 generate 준비 중 중복 spawn2를 재현→FS await 이전 run 슬롯 예약/준비 취소 추적으로 수정했습니다.
- static SDK 추가 조사에서 자동 marker 추가를 확인해 정확한 네 변수/값만 최종 환경 검사에 허용했습니다. 호스트의 그 이름 값을 복사한 것은 아닙니다.
- offline fake에 전달하는 SDK spawn hook도 실제 실행을 거절하도록 강화했습니다. node:child_process.spawn을 스파이로 대체한 RED에서 hook 도달1(실프로세스0)을 재현했고, 수정 후 hook에서 먼저 차단되어 spawn 스파이 도달0입니다(`RED-offlinehook.log`, 최종 실호출감사 테스트).

## 후속 승인·실검증 게이트(이번 완료와 별개)
1. default가 범위를 승인받은 뒤 **동일 자식의 무추론 초기화 가능성과 실제 tokenSource/subscriptionType/firstParty/실효 설정 조합**을 안전하게 관찰·정의해야 합니다. Query 메서드 존재만으로 시작하지 마세요. credential refresh/정책 helper/보조 추론 가능성을 먼저 검토합니다.
2. 본인이 공식 Settings > Usage에서 usage credits 비활성화 근거/시각을 비밀 없이 확인하고, 활성 인증이 API/Console/cloud/gateway/helper가 아님을 확인합니다. 이 앱이 설정/토큰을 조작하지 않습니다.
3. 불명은 AUTH_MODE_UNKNOWN 유지. 증거가 생겨도 현재 코드의 live 게이트를 단순 환경값/boolean으로 열지 말고 같은-child attestation 수명/재검증·입력 장벽을 별도 검토합니다.
4. 그 뒤 별도 bounded 실검색/WebFetch 실제 원문·질문/답변·명시 resume와 callback 소실 복구를 검증합니다. 현재 source 구조 검사를 사실 검증 완료로 대체하지 않습니다.
5. agy pinned version/공식 최소권한을 확인한 뒤 승인된 폴더 한 장 실생성·파일/hash·Windows 실제 취소를 검증합니다. fake provenance를 실제로 바꿔 끼우지 않습니다.
6. I2는 현재 이 어댑터의 정상 경로가 호출을 차단한다는 점을 유지하고 외부 공급자만 명시 테스트 주입으로 연결해야 합니다. 실제 사용자 목표·AC/제출 완료를 선언하면 안 됩니다.
