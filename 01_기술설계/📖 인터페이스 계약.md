# 카드뉴스 실습 — 인터페이스 계약

> 계약 초안 `CN-1` · 2026-10-23 · 상세 설계 결과 **사용자 승인 대기**. 구현/실호출 검증 아님.
> 요구 원본: `../PRD.md:18–68`, `../ACCEPTANCE.md:4–21`. 이 문서가 HTTP·상태·모듈 타입의 단일 기준이에요. 구현 시 공유 타입/런타임 검증은 초안 S0 단독 소유예요.
> SDK는 앱 엔진, agy는 별도 이미지 작업자예요. 본인 Claude 구독 OAuth만 허용하며 API 키/Console 별도 과금/다른 엔진·제공자 fallback은 없어요. HTTP API라는 용어는 **앱 내부 주문 창구**이며 금지한 별도 과금 Claude API 인증과 달라요.

## 후속 확정 — 웹 로그인·진행 표시 보완

이 절은 1인용 로컬 앱에 대한 최신 사용자 승인이다. 기존 원본 PRD·데이터·승인을 보존하며 과거의 구현 전 표기와 정확 버전 고정 조건보다 우선한다. 기존 CN-1 필드와 엔드포인트는 유지한다.

### 진행 이벤트
- 기존 progress 이벤트에 선택 필드 `activity`를 추가한다. 형태는 `{provider:'claude'|'agy'|'app', operation:'authentication'|'search'|'fetch'|'planning'|'image'|'conversion'|'render'|'export', status:'started'|'completed'|'failed'|'waiting', cardId?:string, tool?:string}`. 오래된 이벤트에는 필드가 없어도 유효하다. 카드 식별은 실제 cardId만 사용한다.
- 기존 `message`는 사용자용 한국어 동작 설명, `completed/total`은 실제 완료 카드 수/계획 카드 수 또는 null이다. 검색 진행률·예상 잔여시간을 꾸미지 않는다. 도구의 시작과 종료는 실제 SDK/CLI 이벤트에 근거한다. 모델의 내부 사고·원문 도구 입력/출력·인증값을 중계하지 않는다.
- `AgyAdapter.generate(input,signal,onProgress?)`의 세 번째 선택 콜백은 `{phase:string,message:string,status:'started'|'completed'|'failed'|'waiting'}`를 받아 Promise<void> 또는 void를 반환한다. agy stdout을 종료 후 한꺼번에만 읽지 말고 NDJSON 프레임을 실행 중 파싱해 한정된 generate_image 단계만 전달한다. 중복 step_update는 상태별로 억제하며 UTF-8/줄 경계를 처리한다. worker가 카드 ID를 붙여 Store.appendEvent를 통해 저장한다. 기존 호출자는 콜백 생략 가능하다.
- worker는 카드별 그림 요청·완료·PNG 변환·렌더 시작·완료/실패·export를 실제 처리 경계에서 전달한다. 진행 때문에 승인/콘텐츠 버전을 임의 변경하지 않는다. ready 카드 및 저장된 이미지 재사용 원칙을 유지한다.
- UI는 현재 단계·카드 상태 요약·경과시간·최근 활동 시각·시간순 이력·오류를 표시한다. 새로고침/종료 작업에도 저장 이벤트를 페이지 순서대로 복원하고 project/run/seq로 중복·교차 갱신을 방지한다. 서버 조회 성공 시각과 실제 작업 이벤트 시각은 별도이며 전자를 모델 진행 증거로 취급하지 않는다.
- agy exact-version 거절을 제거한다. 버전은 표시/생성 출처 기록만 한다. 실제 옵션/응답/도구 실패만 관측된 원인으로 보고한다. 429 원문 오류의 안전한 코드/모델/재시도 정보만 추출하고 agy 최종 자연어 설명을 계정 한도 소진 증거로 승격하지 않는다. 실패 원인을 모두 권한 오류로 합치지 않는다.

### 웹 계정 연결
- `src/shared/연결계약.ts`가 추가 API의 타입·Zod 스키마를 정의한다. `ConnectionProvider='claude'|'agy'`.
- `ConnectionState={provider,status:'unknown'|'checking'|'connected'|'login_pending'|'login_required'|'error',version:string|null,authMethod:'subscription'|'google_account'|'unknown',checkedAt:string|null,lastActivityAt:string|null,message:string,errorCode:string|null,operationId:string|null,loginUrl:string|null,needsCode:boolean,verification:'not_checked'|'metadata'}`. 연결 메타데이터 성공을 실제 이미지/검색 성공으로 표시하지 않는다.
- `GET /api/connections` → `{data:{connections:ConnectionState[]}}`. GET은 현재 앱의 관측 상태만 읽고 로그인/모델 호출을 시작하지 않는다.
- `POST /api/connections/:provider/check`와 `/login` → HTTP202 `{data:ConnectionState}`. JSON `{requestId:UUID}`; 같은 ID 재전송은 같은 작업, 동시 로그인/확인은 새 프로세스를 중복 생성하지 않는다. 사용자 웹 동작으로만 시작한다.
- `POST /api/connections/:provider/cancel` → `{data:ConnectionState}`. JSON `{requestId:UUID,operationId:UUID}`. 앱이 만든 해당 로그인 프로세스만 정리하고 기존 사용자 agy/Claude/Hermes는 건드리지 않는다. 로그아웃/인증 삭제는 포함하지 않는다.
- 공식 CLI가 인증 코드를 요구하는 경우에만 `POST /api/connections/:provider/code`, JSON `{requestId:UUID,operationId:UUID,authorizationCode:string}`를 허용한다. 값은 해당 공식 로그인 프로세스 stdin에만 전달하고 DB/디스크/로그/응답에 저장하지 않는다. 브라우저 입력도 전송 후 지운다. 공식 브라우저 callback이 기본이며 비밀번호/API 키 입력칸은 만들지 않는다.
- 기존 localSecurity/Host/Origin/CSRF/JSON 제한을 모든 연결 POST에 적용한다. 공식 로그인 URL은 해당 공급자의 HTTPS 인증 호스트만 허용하고 메모리에서만 전달한다. 범용 URL/명령어/실행 경로 입력 API는 추가하지 않는다.
- Claude는 실제 SDK와 같은 번들 실행 파일·환경의 `auth status`/`auth login --claudeai`와 필요시 무추론 SDK 초기화로 확인한다. Console/API 경로는 허용하지 않는다. agy는 실제 설치 실행 파일의 공식 로그인/모델 목록 흐름을 사용한다. 최초 연결 시 공식 브라우저가 열릴 수 있다는 설명을 UI에 명시한다. 새 OAuth 공급자/토큰 복사/강제 로그아웃/설치/계정·결제 설정 변경은 없다.
- 연결 작업은 유한 타임아웃·중복 방지·취소를 갖는다. 현재 제작 작업 중에는 새 로그인/인증 교체를 시작하지 않고 명확히 안내한다. 정상 사용자 작업 시작 시 기존 동일-query 구독 검사와 실제 도구/파일 검증은 유지한다.

## 1. 공통 규칙

- 기준 주소 제안 `http://127.0.0.1:8765`, JSON UTF-8. 포트 충돌은 종료/안내, 다른 포트는 사용자에게 실제 주소 안내 후 사용. 외부 바인딩/터널 금지.
- 모든 ID는 서버 발급 UUID 문자열. `requestId`만 클라이언트 UUID. `engineSessionId`는 SDK 원형 문자열로 내부 저장하며 공개 응답에서 제외. URL로 공급자 세션 선택 불가.
- 시간은 UTC ISO 8601 `...Z`, UI는 Asia/Seoul와 시간대 표시. 날짜만 확인되면 `YYYY-MM-DD`, 미확인은 `null`(현재 시각을 게시일로 대입 금지).
- 미지 필드/잘못된 enum/중복 배열 값은 422. 문자열은 UTF-8, 빈 문자열 금지; topic 1–500자, instruction 1–4000자, 자유 답변 1–2000자, HTTP JSON 256 KiB 제한. 길이는 JS Unicode code point 기준. 요청 형식 오류 JSON은 400, 크기 초과 413.
- `version`은 양의 정수. 없음을 0으로 쓰는 것은 아직 생성되지 않은 storyboard/result의 내부 카운터에만 허용. 모든 요청 version은 아래 표의 **대상별 버전**이에요.
- 성공 JSON `{ "data": T }`; 실패 `{ "error": AppError }`. mutation 수락은 DB commit 후만 응답. UI는 반환 객체와 GET 스냅샷으로 복원, 낙관적 승인/완료 표시 금지.
- 로컬 앱 세션은 서버 발급 HttpOnly·SameSite=Strict 쿠키와 CSRF 토큰(`X-CSRF-Token`)을 사용. `GET /api/bootstrap` → `{data:{csrfToken,contractVersion:"CN-1"}}`, `Cache-Control:no-store`; Claude 자격증명은 브라우저로 보내지 않음. 개발 Vite origin은 S0가 포트 5173 한 개를 명시 설정, `*` CORS 금지. Host/Origin/Fetch-Metadata 검증, 변경 요청에는 JSON+CSRF 필수. 외부 Origin/Host는 403.

## 2. 스냅샷과 콘텐츠

아래 모든 필드는 필수, `?`만 선택, `|null`은 명시 null. 배열은 빈 배열 허용(최소 수가 별도 표기된 경우 제외). object JSON을 검증 없이 DB에 통째로 반영하지 않아요.

```ts

  sourceId:string; candidateId:string; url:string; title:string;
  publisher:string|null; publishedDate:string|null; eventDate:string|null;
  accessedAt:string|null; primary:boolean;
```

- `period.from` 포함, `period.to=anchorAt` 포함. AI 최신소식 기본 7일, 요청 실행을 접수할 때 서버가 anchorAt 확정. 같은 요청 재전송은 시각을 새로 만들지 않음. 30일 확대 동의 시 같은 anchorAt로 시작점만 확대.
- 후보 7–12개는 목표, 부족하면 실제 수와 부족 이유. 0개도 성공한 조사 결과가 될 수 있으나 selection은 불가. 30일 확대/현재 후보 유지 선택은 앱 질문으로 저장, 자동 확대 금지. `eventKey`로 같은 발표 묶고 서로 다른 sourceIds를 유지. 게시일 최근이라는 이유로 오래된 사건을 새 사건으로 분류하지 않음.
- Source.url은 공개 HTTPS 원문; sourceId 참조는 같은 project 내부에 존재해야 함. `access=opened`와 근거 문장이 없으면 Claim을 verified로 올리지 않음. WebFetch의 가공 결과는 원문 전문 저장/독립 검증과 다름. 기사 요약만으로 원문 확인 완료 금지.
- 선택 범위는 소식(candidateId)의 범위이며 처음 저장한 URL의 고정 목록이 아님. 같은 선택 소식의 공식 발표/제품 문서/변경 기록을 공개 HTTPS로 추가 확인할 수 있다. 새로운 소식 추가·로컬/자격증명 URL·실행 도구 허용으로 확대하지 않는다.
- editorial `sources`는 선택 소식 근거의 추가/갱신분이다. B1은 전체 기존 sources에 sourceId로 병합하고, 미선택 후보의 기존 출처 참조를 보존한다. 동일 sourceId를 다른 candidateId로 재배정하는 충돌은 거절한다.
- 선택 1–3개, 심층 claims는 선택된 후보에서만. hooks 2–3개. 카드 보통 5–8장이나 강제 장수로 삼지 않음; 운영상 방어 상한 제안 20장, 초과 필요 시 기획 변경 결정 요청(자동 자르기 금지).
- 질문 1–4 items, item별 2–4 options(앱 output_size/period는 2개). 자유 입력은 optionIds=[]+text, 선택 답변은 optionIds+text=null. 단일은 정확히 1개, 다중은 1개 이상. 추천 표시는 자동 답변 아님. SDK 원문 question 문자열과 앱 itemId 대응을 내부에 보관.
- result.cards는 카드 ID/개정번호의 불변 manifest. PNG 안에 텍스트를 그린다는 뜻과 별개로 title/body/sourceIds는 구조화하여 별도 편집 가능하게 유지.

## 3. requestId·동시성·응답 재생

1. 프로젝트 변경 요청의 JSON에는 `requestId` 필수. 유일 키는 `(projectId,requestId)`이고 **method+정규화한 route+검증된 payload(requestId 제외)** 전체를 비교. object key 정렬, 배열 순서 유지, optional default 적용 후 canonical JSON을 저장. 지문 충돌에 대비 canonical bytes도 비교. 임의 공백/텍스트를 몰래 다듬지 않음.
2. DB `BEGIN IMMEDIATE`에서 중복 원장 조회 → 같으면 **기존 HTTP 상태와 저장 응답** 재생(헤더 `Idempotency-Replayed:true`), 다르면 409 `REQUEST_ID_CONFLICT`. 최초 202는 완료 후에도 202 수락 영수증으로 재생; 현재 상태는 GET으로 확인. 중복 검사를 version 검사보다 먼저 하므로 이전 성공 재전송은 stale 오류로 바뀌지 않음.
3. 첫 요청에서 version/질문/단계/프로젝트 run lock을 검증, 상태변경+job+outbox/event+request receipt를 같은 트랜잭션에 저장. 응답 손실 후 재요청도 같은 runId. DB busy는 제한된 내부 대기 후 503 `STORAGE_BUSY`로 종료, commit 안 된 요청은 예약하지 않음.
4. 한 프로젝트에 queued/running/waiting_for_user/cancel_requested run 최대 하나(부분 UNIQUE index). 다른 requestId로 같은 실행을 누르면 409 `RUN_ACTIVE`와 기존 runId. 다른 프로젝트는 독립 저장되며 전역 외부 엔진 동시 실행 기본 1(미승인 기본안), 질문 대기는 새 추론/이미지 소비 없음.
5. 단순 구문/값 검증 4xx는 requestId를 소비하지 않음. 트랜잭션 내 도메인 거절(409 등)은 같은 payload에 대해 그 응답을 저장; 수정된 제출은 **새 requestId**. requestId 기록은 프로젝트 생명주기 동안 보존.
6. 프로젝트 생성은 아직 projectId가 없어 예외: `createRequestId`를 JSON으로 받아 로컬 앱 인스턴스 범위 원장에 동일 규칙 적용. 인증 쿠키 갱신과 무관한 instanceId 사용. 취소 요청은 run→project 조회 후 해당 프로젝트 원장 사용. 조회 요청은 requestId 없음.
7. projectVersion은 사용자 도메인 변경/질문 개시·답변/완료 manifest 등록 시 증가; 단순 진행 이벤트/heartbeat는 올리지 않음. researchVersion은 후보 묶음 교체, storyboard.version은 계획 변경, result.version은 승인 대상 변경, card.revision은 해당 카드 변경 시만 증가. CAS로 현재 버전 일치 확인. 오래된 worker는 lease/attempt/base version 모두 확인 후 결과 commit, 불일치면 폐기.

## 4. HTTP 경로 — PRD 초안의 필수 의미 유지

아래 응답 T는 모두 `{data:T}` 안에 들어가요. 표에서 `R`은 requestId:string 필수의 약기이며 실제 필드명은 requestId예요. 모든 mutation은 §3을 적용해요.

| 요청 | 정확한 JSON 입력 | 성공 T와 HTTP | 주요 전제/부작용 |
|---|---|---|---|
| POST /api/projects | `{topic:string,createRequestId:string,period?:7\|30}` | 201 `{projectId,projectVersion:1}` | period 미지정 7, 프로젝트만 생성; 자동 AI 호출 없음 |
| POST /api/projects/{id}/research | `{requestId:string,version:number}` | 202 MutationReceipt | version=projectVersion. topic/selection 단계만 허용, 기존 후속 산출물 있으면 409 STAGE_CONFLICT; job research 생성 |
| GET /api/projects/{id} | 없음 | 200 ProjectSnapshot | no-store, 새로고침 원장. 다른 프로젝트 ID 임의 연결 없음 |
| POST /api/projects/{id}/selection | `{candidateIds:string[],version:number,requestId:string}` | 202 `MutationReceipt & {selectedCandidateIds:string[]}` | version=researchVersion. 선택 단계·열린 확대질문 없음·1–3개; 선택 저장과 editorial job 원자 생성, 선택 후보만 원문 확인 시작 |
| POST /api/projects/{id}/answers | `{questionId:string,version:number,answer:AnswerItem[],requestId:string}` | 202 `MutationReceipt & {questionId:string,questionVersion:number}` | version=question.version. 해당 open 질문·현재 run·모든 item 답변을 검증해 한 번 저장. 아래 질문 종류별 동작 |
| POST /api/projects/{id}/approve | `{stage:'storyboard'\|'final',version:number,requestId:string}` | storyboard:202 MutationReceipt; final:202 `MutationReceipt & {finalApprovedVersion:number}` | storyboard는 storyboard.version, final은 result.version. 승인/production 또는 승인/export job 동시 생성 |
| POST /api/projects/{id}/revisions | `{cardIds:string[],instruction:string,version:number,requestId:string,scope:'storyboard'\|'text'\|'image'\|'layout'}` | 202 MutationReceipt | storyboard scope는 storyboard.version, 그 외 result.version. 카드 존재·중복 없음·run 없음; 세부 규칙 §5 |
| POST /api/runs/{id}/cancel | `{requestId:string}` | 202 MutationReceipt | 기존 run project 범위 원장. 이미 terminal이면 200 receipt(status=기존 status), 실패/완료를 canceled로 덮지 않음 |
| GET /api/runs/{id} | 없음 | 200 Run | 오류/대기/작업 조회 |
| GET /api/projects/{id}/events?after={seq} | 없음 | 200 `{events:EngineEvent[],nextSeq:number,hasMore:boolean}` | seq 기본0, 최대100개, after는 음이 아닌 정수; hasMore면 바로 다음 배치, snapshot이 최종 원장 |
| POST /api/runs/{id}/retry | `{requestId:string,version:number,confirmUnknownOutcome?:boolean}` | 202 MutationReceipt | version=projectVersion. failed/interrupted/canceled만, retryAllowed 확인; 새 runId·이전 run 참조, 시도 디렉터리 새로 생성 |
| POST /api/projects/{id}/cards/{cardId}/approve | `{version:number,resultVersion:number,requestId:string}` | 200 `{projectId,projectVersion,cardId,approvedRevision:number}` | version=card.revision. 현재 manifest의 ready 카드만 개별 승인. final과 별개 |
| GET /api/projects/{id}/assets/{assetId} | 없음 | 200 검증된 이미지 bytes | 현재/보존된 이 프로젝트 미리보기 용도만, 원시 경로 요청 불가. finalized export가 아님 |
| GET /api/projects/{id}/exports | 없음 | 200 `{resultVersion:number,entries:ExportEntry[],exportRun:Run\|null}` | 현재 결과 최종 승인 없으면 409 FINAL_NOT_APPROVED; 준비 중이면 entries=[]와 job, 준비 완료만 목록 노출 |
| GET /api/projects/{id}/exports/{exportId}/download | 없음 | 200 bytes | §7 검증. Content-Disposition:attachment; MIME 고정, no-store, nosniff |

PRD 취소의 ‘입력 없음’은 업무 입력 없음으로 유지하고 requestId 보호만 보강했어요. `scope`, 개별 카드 승인, 조회/이벤트/재시도/다운로드 경로는 PRD 의미 구현을 위한 상세화이며 새로운 외부 서비스 기능이 아니에요. 서버 버전/상태 검증을 UI 비활성화로 대신하지 않아요.

### 질문 처리
- period_expansion: `expand_30` 또는 `keep_current` ID. expand는 period 변경+기존 research run 재개 queued, keep은 기존 후보로 selection 진입하고 해당 run succeeded. 결과 부족을 숨기지 않음. 30일에서도 부족하면 추가 자동 확대 없음.
- editorial: 저장 답변을 해당 SDK tool input으로 번역. live callback이면 같은 run running으로 복귀; 죽은 프로세스면 아래 §6의 명시적 복구 경로 필요. 답변이 받아졌다고 추론 완료를 표시하지 않음.
- output_size: editorial 완료 시 storyboard.size=null이면 같은 완료 트랜잭션에서 앱 output_size 질문(runId=null)을 저장하고 project를 storyboard/waiting_for_user로 둠. editorial run은 succeeded이며 새 inference 없음. 두 크기 선택 후 답변 트랜잭션에서 계획 version 증가, 질문 answered, storyboard/ready로 복귀(status=null인 MutationReceipt), 변경된 version으로 승인. 서버도 size=null 승인은 409 STAGE_CONFLICT로 거절. 1080x1350은 추천일 뿐 기본 승인값 아님.
- stale/answered/superseded/canceled 질문의 새 requestId 답변은 409 QUESTION_STALE. 이전에 수락한 동일 requestId 재전송은 저장 영수증 재생. 답변 트랜잭션 완료 뒤 callback polling으로 전달; HTTP 핸들러가 메모리 Promise를 소유하지 않음.

## 5. 상태 전이·승인 무효화

| 이전 stage/status | 허용 사건 | 다음 상태/의무 |
|---|---|---|
| topic/idle | research 수락 | research/working, run queued→running |
| research/working | 검증된 후보 결과 저장 | selection/ready 또는 research/waiting_for_user(부족 질문) |
| selection/ready | 1–3 선택 저장 | editorial/working |
| editorial/working | SDK 질문 저장 | editorial/waiting_for_user, run waiting_for_user |
| editorial/waiting_for_user | 유효 답변 전달 | editorial/working(재시작이면 interrupted 유지+복구 선택) |
| editorial/working | 원문·계획 결과 저장 | storyboard/ready, run succeeded |
| editorial/working | 크기 미정인 계획 저장 | storyboard/waiting_for_user, 앱 output_size 질문, run succeeded |
| storyboard/waiting_for_user | 유효 output_size 답변 | storyboard/ready, 계획 version 증가, 새 run 없음 |
| storyboard/ready | 현재 계획+size 승인 | production/working, 승인 version 고정, run queued |
| production/working | 모든 실제 이미지·렌더 검증 | review/ready, result manifest 등록 |
| review/ready 또는 export/approved | 대상 카드 revision 수락 | production/working, 즉시 finalApprovedVersion=null·기존 export 노출 해제 |
| review/ready | 현재 result final 승인 | export/approved+export job queued; 완료 후 목록 노출 |
| 임의 active | cancel | run cancel_requested; 정리 확인 후 canceled, project canceled |
| active 오류/소유권 소실 | 오류/lease 만료 | run failed/interrupted, stage 보존, project error/interrupted |
| failed/interrupted/canceled | 유효 retry 수락 | 새 run queued, 실패 단위에서 재개; 자동 외부 호출 반복 금지 |

- storyboard scope 수정: 이미지 제작 전 계획 변경 용도. 선택 원문·독자 맥락 유지, 승인 version 무효화, 수정 계획 준비 후 **다시 스토리보드 승인**. scope가 final 텍스트 수정과 혼동되면 422. 이미지 제작 후 전체 계획 재편은 이번 자동화 밖, 사용자 결정 필요.
- text 수정: 지정 카드 텍스트/sourceIds만 재작성·검증·재렌더, imageAssetId 보존. layout은 deterministic layout만 변경(입력 instruction 해석 필요 시 SDK 사용), 이미지 재생성 없음. image는 지정 카드만 agy 생성/렌더. 범위 밖 카드 revision/imageAssetId/previewAssetId/approvedRevision은 그대로 새 manifest에 참조.
- revision 수락 즉시 result.version 증가+target pending 및 target approvedRevision=null. 나머지 카드 승인 보존. 내용 확정 중인 manifest는 final 승인 불가. 늦게 끝난 과거 export/worker는 현재 버전을 덮지 못함.
- final 전 모든 카드 ready, factsCheck/visualCheck passed 필요. 최종 사용자가 직접 확인해 승인하면 현재 카드들의 approvedRevision도 설정. 기계 검사는 사용자 최종 승인 대체 아님. exporter 실패는 콘텐츠 최종 승인 유지, export retry만 허용. 수정이 오면 즉시 승인 해제.
- run succeeded는 **그 run의 단계 완료**이지 전체 프로젝트 완성 아님. storyboard 계획을 만들었다고 final approved가 되지 않음.

## 6. 엔진 모듈·SDK 실제 경계

### 앱 소유 내부 계약
```ts
type EngineContext = {projectId:string;runId:string;attempt:number;
  engine:'claude-agent-sdk';engineSessionId:string|null;cwd:string;
  phase:'research'|'editorial'|'revision';baseProjectVersion:number};
type EngineEvent = {seq:number;projectId:string;runId:string;attempt:number;at:string} & (
  | {type:'progress';phase:string;message:string;completed:number|null;total:number|null}
  | {type:'need_input';question:Question}
  | {type:'result';kind:'candidates'|'storyboard'|'cards'|'exports';version:number}
  | {type:'error';error:AppError}
);
interface EngineAdapter {
  start(context:EngineContext,input:unknown):AsyncIterable<EngineEvent>;
  answer(context:EngineContext,questionId:string,version:number):Promise<void>;
  status(runId:string):Promise<Run>;
  cancel(runId:string):Promise<void>;
}
```
`input:unknown`는 SDK 입력으로 바로 통과시키는 타입이 아니라 공유 runtime validator로 phase별 ProjectSnapshot/선택/수정 request를 검증하는 경계예요. seq는 project별 DB 단조 증가. progress는 대략의 단계이며 모델 토큰을 퍼센트로 꾸미지 않음. EngineAdapter 외 agy/render/export worker도 같은 이벤트 봉투로 persistence service에 보고해요. public 이벤트에 SDK 원문/tool 결과/숨은 추론/인증값은 보내지 않아요. 결과 이벤트는 DB 결과 commit 뒤에만 생성.

### 공식 SDK로 확인된 부분 [O3–O6]
- `query({prompt,options})`는 AsyncGenerator 기반 Query. `options.cwd`, `resume`, `abortController`, `env`, `settingSources`, `tools`, `canUseTool`, `hooks`, `strictMcpConfig`, `persistSession`은 공식 옵션. 우리 문서의 status/need_input/requestId가 SDK 옵션이라고 주장하지 않음.
- system/init와 result의 `session_id`를 받은 즉시 같은 project/engine에 저장. `resume`에 이 값만 전달, `continue:true`와 가장 최근 세션 탐색은 금지. result type/subtype success와 구조화 출력 검증을 모두 확인; assistant 텍스트가 보였다는 이유만으로 success 금지. 예외와 error result를 한 번의 앱 오류로 정규화.
- research는 tools 배열에 WebSearch/WebFetch만, editorial은 여기에 AskUserQuestion 추가하는 안. 임의 Bash/Read/Write/Edit/Agent/MCP를 제공하지 않음. permissionMode='default'; AskUserQuestion을 선승인하지 않고 canUseTool에서 검증 후 질문으로 변환. `allowedTools`만으로 도구 제한을 주장하지 않음. PreToolUse에서 모든 허용 도구/URL/범위를 재확인하고 불명 도구 deny. connectors는 `strictMcpConfig:true,mcpServers:{}`로 억제.
- `canUseTool(toolName,input,{signal,...})`에서 AskUserQuestion `input.questions`를 검증해 질문과 원 tool-use 대응을 DB에 먼저 기록. callback은 DB 답변을 기다리는 메모리 대기, UI polling은 별도. AbortSignal 구독으로 취소 시 resolver/타이머를 정리. 성공 반환은 `{behavior:'allow',updatedInput:{questions:원질문배열,answers:Record<원질문문장,string>}}`; 다중 선택은 label 문자열을 공식 예처럼 합침, 자유 입력 원문 유지. 서로 같은 question 문장이 중복이면 모호하므로 PROVIDER_PROTOCOL_ERROR로 중단.
- callback 대기는 공식적으로 query 취소 전까지 무기한 가능하지만 **프로세스 종료 뒤 Promise는 사라져요**. DB question/answer는 남음. 살아 있는 worker에서 HTTP 서버만 재시작하면 DB polling으로 계속 처리 가능. worker도 죽으면 interrupted로 전환; 저장 sessionId+답변으로 명시 resume 새 호출을 구성하고 ‘직전 pending tool의 자동 재전달/실행 완료’로 가정하지 않음. pinned SDK에서 pending 질문 재개를 실제 시험해 중복 질문/중복 tool 결과 없는지 확인 전에는 SESSION_RECOVERY_UNVERIFIED로 막고 명시 재시도/새 세션 선택 안내.
- 공식 `PreToolUse`의 defer는 대안 기능이지만 현재 버전/재개 프로토콜 미검증이므로 CN-1 구현 의무로 쓰지 않음. 메모리 callback 기본과 혼합하여 ‘영구 대기 자동 복구 보장’하지 않음.

### 구독 인증 preflight — 추론 전 반드시 통과 [O1–O3,O7]
1. 프로필/호스트 환경 전체 복사 금지. worker의 **자식 전용 env allowlist**로 PATH·SystemRoot·USERPROFILE·APPDATA·LOCALAPPDATA·TEMP/TMP 등 실행에 필요한 값만 전달, 값은 로그 금지. SDK `env`는 공식상 교체(replace)이며 병합 아님. child spawn에서 실제 최종 전달 env도 검증. `ANTHROPIC_*`, `CLAUDE_CODE_USE_*`, `CLAUDE_CODE_OAUTH_TOKEN`, provider-managed-by-host·gateway·proxy·WIF/클라우드 인증 관련 경로는 기본 미전달. native SDK가 필수로 추가하는 값은 pinned 소스 확인 후 허용 명시; 임의 새 이름은 거절. 호스트 env를 unset/변경하지 않음.
2. `settingSources:[]`, `strictMcpConfig:true`, `mcpServers:{}`, 자동 메모리 비활성화로 사용자/프로젝트 helper·hooks·connector를 의도치 않게 실행하지 않음. 그러나 **managed policy와 global .claude.json은 여전히 읽혀요**. `resolveSettings()`는 공식 alpha이며 policyHelper를 실행하지 않고 server-managed 설정을 fetch하지 않으므로 완전한 실효 설정 증명이 아님. 감지되는 apiKeyHelper/env/provider/profile/gateway 경로는 거절. 전체 설정 본문/credential stores는 출력·복사 금지.
3. `CLAUDE_CONFIG_DIR`의 기존 본인 구독 로그인 위치를 유지하는 것이 기본안. 격리 디렉터리를 새로 정하면 기존 로그인은 자동 이동하지 않으며 **본인이 공식 로그인하는 추가 승인**이 필요; 토큰/credential 복사 금지. 전역/managed config에 남은 API·프로필·gateway 선택을 per-invocation documented 옵션만으로 무력화/관측할 수 없다면 `AUTH_MODE_UNKNOWN`으로 종료. 바이너리 패치/host 정책 수정/강제 로그인 설정으로 우회하지 않음. `forceLoginMethod:'claudeai'` 하나도 완전한 과금 차단 근거가 아님.
4. 추론을 담지 않은 입력 장벽을 설계해요: AsyncIterable prompt는 **검증 전 아무 user message도 yield하지 않음**. Query의 공식 `initializationResult()`/`accountInfo()`로 그 **동일 자식**의 subscriptionType·tokenSource·apiKeySource를 판독하는 bounded 검증 후보. 이 메서드들은 문서상 존재하나 입력 대기 중 초기화 가능성/무추론/부수효과와 enum 값 매핑은 현재 기기에서 미검증. `startup()`의 WarmQuery에는 accountInfo가 문서화돼 있지 않으므로 임의 메서드를 만들지 않음.
5. 후속 G1에서 고정 SDK/번들의 공식 타입·소스·안전한 실제 metadata를 대조해 `authMode='subscription_oauth'`의 **양성 증거 조합**(active token source가 본인 claude.ai /login, subscriptionType이 유효 구독, provider=Anthropic 직접, helper/API/Console/profile/WIF/cloud/gateway 미선택)을 정의·기록해야 함. AccountInfo 필드들은 optional string이며 공식 enum이 아니므로 지금 임의 `'oauth'` 문자열 비교로 구현 금지. 관측 누락/상충/재검증 불가면 장벽을 열지 않음. 초기화가 입력을 요구하거나 모델 호출을 이미 시작하는 버전이면 이 접근을 폐기하고 blocker로 올림. `apiKeySource='none'`, OAuth라는 단어, 비용0, 모델 응답 성공만으로 구독 입증 불가(Console도 OAuth 가능).
6. 동일 자식의 승인된 auth attestation(비밀 없는 mode/version/검증시각/설정지문/근거 필드만)을 메모리에 보유하고 나서만 첫 prompt release. 재시작/새 자식/설정 변경/인증 오류/갱신에는 재검증. 사전 검증 자체가 네트워크/credential refresh 가능하므로 **현재는 실행하지 않음**. 미래 실호출은 default가 사용자 범위 승인을 받은 뒤, 비추론 검증 성공 다음의 별도 bounded 검색/질문/재개 시험으로 진행.
7. 구독 만료/한도/검색 비지원/취소 및 외부 결과 불명은 명시 오류. **사용량 크레딧(usage credits/이전 extra usage)도 별도 과금이므로 금지**. O15 공식 안내상 켜져 있으면 구독 한도 이후 API 요율의 추가 청구로 계속될 수 있어, 단순 subscription_oauth 판정만으로 충분하지 않음. 본인이 공식 `Settings > Usage`에서 **usage credits 비활성화**를 확인한 비밀 없는 근거와 시각을 제출한 뒤에만 G1 실호출 허용. enabled 또는 확인 불명은 AUTH_PATH_FORBIDDEN/AUTH_MODE_UNKNOWN으로 차단, 앱이 충전/auto-reload/결제 설정을 조작하지 않음. SDK cost/usage/maxBudgetUsd는 청구원/구독 한도 차단 증거가 아님. 한도 소진 시 중단, 별도 API·CLI·다른 모델/제공자 자동 fallback 없음. 실제 검증 시 공식 경로와 동작을 재확인하며 계정 설정 변경은 본인이 별도 승인 범위에서 수행.

이 preflight의 **실현 가능성 자체가 G1의 선행 검증 대상**이에요. 현재 설계는 모르는 상태에서 호출하지 않는 구현을 요구하며, 구독 성공을 보장하지 않아요. G1이 막혀도 F1/B1/R1의 오프라인 작업은 병렬로 진행할 수 있고 실연동 성공으로 제출할 수는 없어요.

### 후속 승인 보완 — 실행 소유자가 취소 결과를 확인해 반환

W1 차단 원인 확인 후 사용자가 ‘위 범위로 기존 W1 수정·재개’를 승인했어요. SDK/agy 실행 소유자가 자신이 만든 프로세스의 신원과 종료를 확인하고, W1은 그 결과만 소비하는 방식으로 보완해요. W1에 임의 프로세스 검색·강제 종료 책임을 떠넘기지 않아요. 외부 HTTP 계약과 contractVersion=CN-1은 바꾸지 않는 내부 수명주기 계약 보완이에요.

- 내부 `CleanupReport` 핵심 필드: `runId: string | null`, `status: 'confirmed' | 'not_started' | 'failed' | 'unknown'`, `verifiedAt: string`, `reason: string | null`, `children`(아래 자식별 증거 배열).
- 자식별 증거: PID, 부모 PID, 실행파일 경로, 실제 생성시각, 신원 확인 여부, 종료 확인 여부와 하위 실행 정리 확인 여부. 확인 불가 값은 null/미확인으로 남기고 성공으로 바꾸지 않아요. 명령행·환경값·토큰·인증정보는 기록하지 않아요. 실제 OS 관찰과 테스트 대역 증거를 구별해요.
- `EngineAdapter.cancel(runId)` 및 `AgyAdapter.cancel(runId)`은 `Promise<CleanupReport>`를 반환해요. `ClaudeAdapter.dispose()`와 `AgyAdapter.dispose()`는 소유한 실행별 `CleanupReport[]`를 반환해 종료 실패를 숨기지 않아요. 기존 호출자가 결과를 무시해도 호출 형태는 유지되지만, 취소 완료를 판정하는 W1은 반드시 결과를 검사해요.
- `confirmed`: 해당 실행의 작업 종료와 실제 시작된 소유 자식/하위 실행의 종료가 확인됐을 때만 반환해요. abort 신호·kill 요청·메서드 반환·시간 경과만으로 confirmed를 만들지 않아요.
- `not_started`: 해당 실행이 이 소유자에게서 시작되지 않았다는 추적 근거가 있을 때만 사용해요. 현재 map에 없다는 사실만으로 과거/다른 시도의 프로그램까지 종료됐다고 가정하지 않아요. W1은 자기 현재 시도의 시작 기록과 맞춰 실제 취소 완료가 가능한지 판단해요.
- `failed`/`unknown`: 종료 실패·아직 실행 중·신원 또는 하위 실행 종료를 확인하지 못한 경우예요. W1은 `cleanupConfirmed:true`를 저장하지 않고 취소 확인 실패/미확인 상태와 다음 조치를 표시해요.
- 실행 소유자는 자신이 시작한 ChildProcess와 추적 기록을 유지하고 신원을 확인한 대상만 정리해요. PID 재사용·다른 실행·Hermes·사용자 브라우저를 종료하지 않아요. 원시 프로세스 핸들은 W1에 넘기지 않아요.
- SDK/agy의 기존 실행 차단과 구독 전용 조건은 그대로 유지해요. 이번 검증은 로컬 테스트용 프로그램과 명시된 테스트 대역만 사용하고 실제 SDK 초기화/검색/이미지 생성은 실행하지 않아요. 렌더는 기존 `finally`의 browser.close 완료를 기다리는 경계를 유지하고, 그 밖의 정리 상태가 미확인이면 성공으로 확대하지 않아요.
- 이번 보완에 한해 기존 W1이 shared 계약/포트·SDK/agy 연결부·그 프로세스 정리 helper·관련 shared/provider/worker 테스트를 단독 수정해요. 기존 S0/G1은 완료 상태, I2는 W1 선행 대기라 병렬 쓰기 충돌이 없어요. 외부 HTTP/DB/프론트/렌더 요구를 변경하지 않아요.

### 후속 승인 확정 — layout 실제 반영과 완료 기록 원자 저장

사용자가 ‘권장 수정안으로 한 번에 진행’을 선택했어요. 아래는 미정 선택지가 아니라 이번 보완에서 적용할 결정이에요. 기존 W1이 관련 shared/provider/render/backend/worker와 직접 영향 테스트를 단독 수정해요. 다른 모듈의 새 기능·실호출·인증 방식 변경은 포함하지 않아요.

1. **layout은 실제 배치 변경이에요.** 같은 템플릿을 같은 입력으로 다시 찍는 것으로 수정 성공을 대체하지 않아요. CardRevision에 하위 호환 가능한 선택 필드 `layout`을 추가하고, 있으면 `{fontScale:'small'|'normal'|'large', textAlign:'left'|'center', placement:'top'|'bottom'}`의 세 항목을 모두 갖도록 검증해요. 없으면 기존 카드의 실제 모습(정상 글자 크기·왼쪽 정렬·본문 아래 배치)을 그대로 유지해요. 원본/기존 저장 데이터는 파괴적으로 재작성하지 않아요.
2. 모델이 임의 CSS/HTML/JS를 넘기는 것은 금지하고 위 허용 옵션만 전달해요. SDK revision 출력 검증→worker→저장소→RenderInput.card→고정 템플릿의 안전한 클래스/변수에 연결해요. API의 기존 layout 수정 scope와 instruction은 유지하고, 옵션이 바뀌면 실제 출력에도 반영돼야 해요. 지원 범위 밖 지시는 명확한 실패/추가 질문으로 처리하며 가짜 성공으로 만들지 않아요. 실제 SDK 호출은 이번에도 하지 않아요.
3. layout 수정은 대상 카드의 layout만 바꾸며 제목·본문·출처·그림/그림계획·비대상 카드 자산과 승인 상태는 보존해요. text/image 수정도 기존 layout을 이유 없이 지우지 않아요. 현재 결과 버전/대상 revision/최종 승인 해제 규칙은 그대로예요. 새 편집기나 자유 배치 도구는 만들지 않아요.
4. **terminal committed journal은 Store.commit 내부에서 원자 저장해요.** 완료 후 Store.journal을 호출하거나 완료 전에 committed를 선기록하는 우회는 쓰지 않아요. 성공/실패/취소 등 실제 terminal 상태로 확정하는 동일 DB 트랜잭션에서 최종 결과/상태·종료 기록·event를 함께 저장하고, 하나라도 실패하면 모두 롤백해요. 아직 running/waiting/cancel_requested인 중간 결과를 최종 완료로 기록하지 않아요.
5. 종료 기록은 기존 InvocationMark 형태의 `state:'committed'`를 사용하고, terminal run/attempt에 결속한 단일 최종 기록으로 남겨요. phase는 `terminal_commit`, cardId/expectedPath/sha256은 null을 사용할 수 있어요. 필요 정보는 기존 결과 manifest/event와 연결하며 다른 임시 기록 규칙을 약화하지 않아요. Store.commit 반환 성공은 이 원자 저장이 완료됐다는 뜻이고, worker는 그 뒤 terminal journal을 덧붙이지 않아요. terminal/오래된 소유자의 임의 journal 쓰기를 허용하도록 active/fence 검사를 느슨하게 만들지 않아요.
6. 검증은 실제 로컬 DB와 렌더러로 해요. 같은 문구·그림에서 layout 변경 후 DOM 배치/글자 크기/PNG 결과가 달라지는지, 비대상과 원본 그림이 보존되는지 확인해요. terminal 결과와 committed 기록의 동시 저장 및 실패 시 동시 롤백을 검사해요. 실제 AI/검색/agy 생성은 0회로 유지해요.

## 7. agy·렌더·출력 계약

### agy adapter
- `spawn(검증된 agy 절대경로,['-p',prompt,'--output-format','json'],{cwd:attemptDir,env:sanitizedEnv,shell:false})` 형태 제안. prompt/경로는 독립 인자, 셸 문자열 금지. 공식은 -p/JSON envelope를 지원하지만 pinned 로컬 버전과 이미지 권한은 미검증.
- 공식 JSON 예의 `conversation_id`, `status`, `response`, `duration_seconds`, `num_turns`, `usage`를 파싱. SDK session_id와 섞지 않음. `status=SUCCESS`/exit0도 파일 성공 증거 아님. 응답의 별도 assetPath 고정 필드는 공식 근거가 없으므로 요구하지 않음.
- 생성 prompt에 앱이 만든 예상 파일명 `image.png`, 장면·구도·공통 색·텍스트 빈 공간·그림 안 글자 없음 명시. 시도 폴더의 실제 image.png와 반환 서술 경로(있는 경우)를 대조. 다른 경로/추가 파일은 자동 수집하지 않음. JSON/파일 부재/권한 soft deny는 IMAGE_GENERATION_FAILED/TOOL_PERMISSION_DENIED. `agy image generate` 없음. 전면 permission skip은 기본안 제외, 정확한 최소 이미지 도구 허용 규칙은 후속 버전/계정 시험 전 provisional.
- 이미지 검증: regular file·realpath가 attemptDir 내부·symlink/junction/ADS/UNC/드라이브 탈출 거절·PNG magic+실제 decode·양의 크기·50MiB/4096×4096 상한 제안·sha256·mime=image/png. 생성 원본 크기는 최종 카드 크기와 달라도 됨. 예상 파일만 immutable assetId에 원자 등록. 생성 tool/date/prompt/약관 확인 상태/illustrative=true 저장. 샘플 PNG를 실제 생성으로 대체 금지.

### RenderInput/RenderOutput(앱 내부, renderer에 DB 쓰기 권한 없음)
```ts
type RenderInput = {projectId:string;runId:string;attempt:number;
  resultVersion:number;card:CardRevision;size:Size;
  image:{assetId:string;absolutePath:string;sha256:string};
  researchAt:string;sourceLabels:{sourceId:string;label:string;url:string}[];
  font:{family:'Noto Sans KR';absolutePath:string;licenseAssetId:string};
  templateVersion:'cn-basic-1';outputPath:string};
type RenderOutput = {projectId:string;resultVersion:number;cardId:string;cardRevision:number;
  path:string;mimeType:'image/png';width:1080;height:1350|1080;
  sha256:string;bytes:number;checks:{fontLoaded:boolean;imageDecoded:boolean;overflow:boolean};
  warnings:string[]};
```
- absolutePath/outputPath는 worker가 검증한 내부 값, HTTP/모델이 주지 않음. card.previewAssetId는 새 생성 전 null일 수 있음. renderer는 escaped text와 고정 앱 템플릿만 사용, 임의 HTML/CSS/JS 입력 금지. image/font만 허용된 로컬 asset, 외부 fetch는 차단.
- CSS viewport=선택 크기, deviceScaleFactor=1 제안. document.fonts.ready·이미지 decode·layout 안정화 후 카드 요소 PNG. 글꼴 누락/텍스트 overflow면 실패, 자동 잘림으로 통과 금지. 실제 decode width/height와 PNG magic/해시 확인 후 worker가 자산 등록. 미리보기는 이 PNG를 사용하고 편집값은 별도 폼으로 수정.
- 출력 manifest는 resultVersion과 order/cardId/revision/assetId/hash를 고정. ZIP에는 순서 있는 카드 PNG, `출처기록.json`, `이미지기록.json`, `글꼴라이선스.txt` 포함 제안. source record는 period/원문/날짜/access/evidence/claims, image record는 tool/version/생성일/prompt/크기/hash/사용조건/생성 이미지 고지. 외부 스톡을 쓰면 작가·원문·라이선스·필수표기 추가, 조건 미확인이면 사용 금지.
- 다운로드는 매번 project/current result/finalApprovedVersion/export 완료/파일 realpath·hash를 검증. 수정 후 과거 exportId도 409 EXPORT_STALE(숨겨진 과거 승인물을 새 결과로 노출 금지). 미완성/오류 파일은 목록에 없음. 클라이언트가 경로를 URL 인자로 전달하는 기능 없음. ZIP은 파일 순서/수량/CRC/실제 PNG 열림 검사 필요. PDF는 CN-1 필수/카드 범위 아님.

## 8. 오류·타이밍·UI 상호작용

| code | HTTP(동기) | 의미/다음 행동 |
|---|---|---|
| VALIDATION_ERROR / INVALID_JSON | 422 / 400 | field/입력 수정 |
| NOT_FOUND | 404 | 없는 project/run/asset 또는 프로젝트 밖 식별자 |
| LOCAL_REQUEST_DENIED | 403 | Host/Origin/CSRF 불일치 |
| VERSION_CONFLICT / QUESTION_STALE / REQUEST_ID_CONFLICT | 409 | 현재 스냅샷 재조회/새 요청, 자동 덮어쓰기 금지 |
| STAGE_CONFLICT / RUN_ACTIVE / FINAL_NOT_APPROVED / EXPORT_STALE | 409 | 현재 단계/기존 작업/재승인 안내 |
| AUTH_PATH_FORBIDDEN / AUTH_MODE_UNKNOWN | 409 | 비구독 또는 불명; 추론 금지·본인 확인 |
| LOGIN_REQUIRED / SUBSCRIPTION_EXPIRED | 409 | 공식 로그인 필요; 앱에서 토큰 수집 금지 |
| SUBSCRIPTION_QUOTA | 429 | 재설정 시각이 확실할 때만 retryAfter, 기다리기 |
| SEARCH_TOOL_UNAVAILABLE / TOOL_PERMISSION_DENIED | 409 | 도구 권한 확인, API 대체 금지 |
| RESEARCH_FAILED / PROVIDER_PROTOCOL_ERROR | 502 | 원문/출력 검증 실패, 이유 표시 후 명시 재시도 |
| IMAGE_GENERATION_FAILED / ASSET_INVALID / RENDER_FAILED | 502 | 해당 카드만 실패/재시도 |
| STORAGE_BUSY / EXPORT_FAILED | 503 / 500 | DB 대기/저장 공간/묶음 확인 |
| SESSION_RECOVERY_UNVERIFIED / EXTERNAL_OUTCOME_UNKNOWN | 409 | 중복 외부 요청 가능성 표시, 확인 후 재시도 |
| CANCEL_CLEANUP_FAILED | 500 | 취소 요청 유지/중단 표시, 정리 확인 필요 |

비동기 오류는 이미 수락된 HTTP를 뒤늦게 502로 바꾸지 않고 GET Run.error/event로 전달해요. 일반 500은 내부 진단 ID만, 원시 stderr/스택/비밀 노출 금지. cancel은 API/SDK 응답보다 하위 앱 소유 프로세스 정리가 완료되어야 canceled. 다른 프로세스/Hermes 정리 금지.

- HTTP mutation 목표 <1초(보장 측정값 아님), 외부 작업 기다리지 않음. polling은 active 1초, waiting 3초, 백그라운드 탭 5초 제안; 네트워크 실패시 2/4/8/최대15초 backoff. terminal 후 자동 폴링 정지, 사용자 동작/새로고침 때 재조회. waiting은 오류 토스트/무한 실패 재시도로 표현하지 않음.
- worker lease 30초·heartbeat 5초, callback 대기 중에도 갱신. 정리 grace 10초 제안, 초과 시 CANCEL_CLEANUP_FAILED/unknown. 숫자는 구현 후 실측 조정 대상으로 기록.
- 화면 이벤트는 주제 제출, 후보 선택 제출, 질문 답변, 계획 승인/수정, 카드 지정 수정/승인, 최종 승인, 취소/재시도, 다운로드뿐. action 입력 version/requestId를 생성하고 네트워크 재전송은 같은 ID 유지. 응답 후 스냅샷을 재조회. 구현 없는 DOM selector/event bus 규약은 만들지 않음.
- 저장 상태와 화면 요청 중 상태 분리: 로딩/전송 중/정상 대기/실행/부분 실패/취소 중/중단 복구/완료 표시. mock 모드는 상단에 ‘모의 데이터·실제 조사/생성 아님’, real 작업에 fixture 유입 금지.
