## 5. 공통 화면 수용 기준

1. 차단된 버튼/숨겨진 행동 가까이에 이유와 다음 행동을 표시한다. hover의 title이나 색상만으로 전달하지 않는다.
2. 오류는 무엇을 하다 막혔는지, 필요한 사용자 행동, 안전한 재시도 조건을 설명한다. 내부 코드만 노출하지 않는다.
3. 상세 메모·원시 로그를 찾아야만 원인을 알 수 있는 상태를 해소한다. 원문 응답·비밀값·로컬 인증 경로는 노출하지 않는다.
4. UI가 권하는 행동은 현재 서버가 수락하는 행동과 같아야 한다. 지원하지 않는 복구는 지원하지 않는다고 표시한다.
5. 작업 실행 성공·검수 통과·최종 승인·파일 준비·실제 다운로드를 별도 상태로 보여준다.
6. 단순 체크박스나 비활성 조건 제거로 내부 검사를 통과한 것처럼 위조하지 않는다.

테스트 142개 중 관련 기대 동작을 정적으로 대조했으며 전체를 실행/통과한 것이 아니다. 뷰포트별 가림·다운로드 실패 시 브라우저 동작·모든 실패의 실사용 재현·새 OAuth/실계정 logout·추가 provider 요청은 수행하지 않았다. 최근 프로젝트 상태는 기존 저장 기록을 인용했으며 이번 DB 재조회/변경은 없다. 제안된 새 API/사유 코드·복구는 아직 구현되지 않았다.

## 8. 결함으로 세지 않은 사항·남은 확인

- 스토리보드 버튼은 ‘승인 · 제작 시작’이고 서버도 함께 enqueue한다. 별도 제작 버튼 누락은 아니다.
- 개별 카드 승인은 최종 승인의 필수 선행이 아니다. 최종 승인에서 모든 현재 개정을 승인한다(`src/backend/저장소.ts:188`). export의 개별 승인 버튼이 정상 상태로 활성이라는 의심도 반증됐다.
- 30일 조사에 expand_30 질문이 다시 생성된다는 의심은 days===7 생성 조건으로 반증됐다(`src/backend/저장소.ts:265`).
- 구독 OAuth 전용·금지 API 경로·도구 목록·소유/종료 증거·lease/fence·버전/요청 원장·현재 승인/자산 해시는 유지할 보호 장치다.
- 후보 1~3개, 질문 대기는 정상, 취소 접수/완료, 결과 불명 확인, 활성 작업 삭제 금지·영구 삭제 확인은 이미 안내가 있다.
- Gemini 일반 quota/이미지 전용 잔여량 미제공, metadata와 생성 성공 구분, 이전 조회값/미확인 표시는 이미 존재한다.
- CSS가 전체 오류 안내를 숨기는 규칙은 발견하지 못했다. 모바일 보조 문구·사용량 상세 분리는 다르며 실제 가림은 별도 시험이다.
- native metadata와 SDK enterprise 허용 범주 차이는 정책/반환값 추가 확인 대상이지 이번 확정 인증 결함은 아니다.
- 새 OAuth·실계정 logout·실제 전체 제작/다운로드·현재 제공자 한도/worker 생존은 이번 정적 점검으로 갱신하지 않았다.
