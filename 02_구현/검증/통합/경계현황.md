### 합성 주입과 재시작의 정확한 범위
- `createStore({dataMode:'mock', dbPath:I1 전용, dataDir:I1 전용})`와 실제 `Store.claimJob`/`Store.commit(content:candidates)`만으로 **저장할 조사 결과를 명시 주입**했다. 뉴스는 실제 검색 결과가 아니다. UI는 `<App/>` real HTTP이며 snapshot.dataMode=mock이 합성 고지를 유발한다. `createMockClient`를 주입하지 않았다.
- 실제 research HTTP는 queued 작업을 접수할 뿐이고 공급자/worker factory를 호출하지 않는다. 전역 실행 1 제한을 지키기 위해 앞선 테스트의 **외부 실행 전 editorial**을 실제 cancel HTTP+저장 commit(canceled)으로 정리한 뒤 다음 seed를 claim한다. 결과 JSON에 `storage-only-cancel-unexecuted`가 기록된다. 이는 실제 SDK 자식 취소 증거가 아니다.
- 영속 복원은 **동일 하네스 프로세스 안의 Express 앱 재생성 및 SQLite Store close/reopen**이다. OS 서버/worker 프로세스 재시작, lease reconcile, 질문 callback 복구는 검사하지 않았다. 재시작 대상의 선택은 유지되고 미실행 editorial은 앞선 합성 seed 준비에서 취소된 상태도 그대로 보존한다.
- provider/SDK/agy/worker import·factory 실행 없음, 브라우저는 정확한 자체 loopback origin 이외 요청만 abort한다. API response fulfill/mock/intercept는 없다. 실호출 **0회**이며 외부 인증 저장소/계정 설정은 읽거나 바꾸지 않았다.
