## 형제 작업자 실행법(재설치하지 마세요)
Git Bash에서 **APP로 이동한 후** 아래를 실행합니다. node 별칭/winpty/npx를 사용하지 않습니다.
```bash
(
  NODE="$PWD/.도구/node-v24.22.1-win-x64/node.exe"
  NPM="$PWD/.도구/node-v24.22.1-win-x64/node_modules/npm/bin/npm-cli.js"
  export PATH="$PWD/.도구/node-v24.22.1-win-x64:$PATH"
  export npm_config_userconfig="$(pwd -W)/.도구/npmrc"
  export npm_config_globalconfig="$(pwd -W)/.도구/global-npmrc"
  export PLAYWRIGHT_BROWSERS_PATH="$(pwd -W)/.브라우저"
  # CARD는 본인 카드 namespace(B1/F1/G1/R1/W1/I1/I2). 해당 폴더는 본인 승인 범위에서 준비.
  CARD=B1
  export npm_config_cache="$(pwd -W)/실행데이터/$CARD/npm-cache"
  export TEMP="$(pwd -W)/실행데이터/$CARD/임시"
  export TMP="$TEMP"
  "$NODE" "$NPM" run typecheck
  "$NODE" "$NPM" run test:backend
)
```
- `TEMP/TMP`, DB, 출력·로그는 자기 카드 namespace만 쓰세요. Vitest cache=false, 공용 reporter 출력은 stdout입니다. frontend suite는 jsdom으로 실행하며 jest-dom matcher가 필요하면 테스트에서 `@testing-library/jest-dom/vitest`를 명시 import합니다.
- full build/dist는 S0와 마지막 I2만 순차 실행합니다. feature 카드는 본인 suite+typecheck만 실행하세요. 공유 package/lock/config/shared/bootstrap을 직접 고치지 마세요.
- renderer는 `.브라우저` 환경을 **Playwright import 전** 설정하거나 RenderOptions.browserExecutablePath를 전달하세요. import 뒤 env 설정은 이미 결정된 browser registry를 바꾸지 못할 수 있습니다.
- S0 재검사 명령: 전용 node로 `scripts/골격검사.mjs`. 설치/재검사는 승인 범위를 재확인한 뒤 실행해야 합니다. 이 helper는 S0 전용이므로 다른 카드의 데이터 출력에 사용하지 마세요.

## 정확한 모듈 연결 계약
**요약 대신 실제 `src/shared/포트.ts`를 먼저 읽으세요.** DTO/validator는 여기서 재수출합니다. factory 타입은 구현 존재 선언이 아닙니다.
| 소유자/모듈 | named export / 공유 함수 타입 |
|---|---|
| B1 `src/backend/저장소.ts` | `createStore: CreateStore = (StoreOptions) => Promise<Store>` |
| B1 `src/backend/앱.ts` | `createApp: CreateApp = (AppOptions) => Express` (listen하지 않음) |
| G1 `src/providers/클로드.ts` | `createClaudeAdapter: CreateClaudeAdapter = (ClaudeOptions) => ClaudeAdapter` |
| G1 `src/providers/agy.ts` | `createAgyAdapter: CreateAgyAdapter = ({executablePath,livePermission,clock?}) => AgyAdapter` |
| R1 `src/render/렌더러.ts` | `renderCard: RenderCard = (DeepReadonly<RenderInput>,RenderOptions?) => Promise<RenderOutput>` |
| R1 `src/render/내보내기.ts` | `buildExport: BuildExport = (DeepReadonly<ExportInput>,{signal?}?) => Promise<ExportOutput>` |
| W1 `src/worker/작업자.ts` | `createWorker: CreateWorker = (WorkerOptions) => Worker` |
| F1 `src/frontend/App.tsx` | `App: FrontendApp = (AppProps) => ReactElement` (named 필수/default 추가 가능) |

- Store.mutate와 FrontendClient.mutate는 동일 MutationName/Target/RequestByMutation/ResponseByMutation을 사용합니다. Store는 status/body/replayed를 반환하고 frontend client는 data를 반환/실패 `{status,error:AppError}`를 throw합니다. HTTP는 CN-1 경로 그대로이며 내부 generic 이름은 새 HTTP 프로토콜이 아닙니다.
- B1은 DB에서 method+정규 route+검증 payload(requestId 제외)를 비교하고 저장 응답/status를 CAS보다 먼저 재생합니다. `canonicalJson`은 object key 정렬만 하며 배열/공백/Unicode는 보존합니다. requestId 원장·중복 실제 transaction 검증은 B1 소관으로 S0 통과 주장 없음.
- Store의 lease/질문/session/journal/commit/reconcile port를 W1이 사용합니다. owner/attempt/fence/baseVersion 검사, 결과/자산/event 원자 commit. saveQuestion/commit은 새 fence를 반환합니다. 저장된 현재 질문 답변 transaction의 새 base는 readAnswer의 반환 fence로만 채택하고 임의 최신 snapshot으로 갱신하지 않습니다.
- W1은 run별 ProviderBridge closure를 만들고 createClaudeAdapter에 전달합니다. G1의 progress/question/result/error는 bridge를 통해 DB에 먼저 저장하고 **이미 seq가 할당된 이벤트만** start에서 yield합니다. W1은 이를 다시 append하지 않습니다. DB 답변 polling·AbortSignal·질문 mapping·session 명시 저장을 사용하며 HTTP가 callback Promise를 소유하지 않습니다.
- EngineContent는 candidates/storyboard/cards의 앱 내부 결과이며 공개 result event에는 버전만 있습니다. revision의 대상 내용만 새 개정, 비대상 revision/자산/승인 보존은 B1/W1의 원자 commit 의무입니다. DTO는 데이터 형태/관련 불변 조건을 검사하며 DB atomicity를 구현하지 않습니다.
- 외부 auth attestation은 G1이 동일 자식에서 직접 확인하여 내부 보유해야 합니다. 호출자가 전달한 인증 객체는 양성 인증 증거가 아닙니다. 현재 LivePermission은 모두 false로만 사용해야 합니다. live hook은 환경변수로도 열리지 않는 차단용 future hook입니다.
- Renderer/exporter는 DB 권한 없음. export 입력의 manifest는 카드별 revision/order/PNG 자산을 고정하며 imageRecords는 원본 image 자산(hash/size)과 생성 provenance를 함께 전달합니다.
- createWorker.start는 loop 준비 후 resolve, tick은 최대 1 claim 처리, stop/dispose는 생성한 SDK/자식 정리까지 대기. 주입된 Store/agy의 최종 close/dispose는 조립한 호출자가 담당하고 renderer는 자신이 연 브라우저를 finally close합니다.
- 기본 최대 외부 실행1은 리소스 안전 제한이며 질문 대기는 추론을 새로 소비하지 않아야 합니다. 실제 provider/session/restart/Windows 취소는 후속 검증 대상입니다.

- 통합 `--checkpoint=storage|question|production|export`는 각각 저장연결/질문연결/제작연결/수정출력 이름으로 필터합니다. 현재 파일이 없어 NOT_READY이며, 실제 파일을 이용한 checkpoint 실행은 I1에서 확인해야 합니다.

## 남은 검증
- feature 모듈·HTTP 보안/인가·지속 job/DB 동시성·진짜 renderer PNG/ZIP·브라우저 UI 전체 흐름은 아직 없습니다. 공유 ports의 정적 연결과 scaffold만 검증했습니다.
- subscription OAuth 양성/usage credits 비활성화/무추론 장벽·WebSearch/WebFetch·SDK 질문 재개·agy 이미지 생성/취소는 **미검증/이번 승인에서 실행 금지**입니다. Unknown은 G1에서 fail-closed, production mock 자동 대체 금지입니다.
- PublicUrlSchema는 구문 수준 검사입니다. DNS/redirect egress 격리·실제 접근 가능성·원문 사실 확인은 G1의 별도 책임입니다.
- 글꼴 로드 성공은 최종 카드의 한국어 잘림·대비·375px 가독성 검증이 아닙니다. 출력 파일의 실제 bytes/hash/ZIP CRC는 R1 및 I1/I2에서 확인합니다.
