# 실행 안내 — 웹 계정 연결과 작업 진행 표시

## 최신 화면 보정 — 기본 페이지 스크롤
- 본문과 작업 이력에 있던 내부 스크롤 상자를 없앴다. 마우스 휠은 브라우저 페이지를 움직이며, 작업 이력을 펼치면 문서가 길어진다. 이력은 제목을 눌러 접을 수 있다.
- 데스크톱 사용량은 본문 아래의 빈 띠가 아니라 오른쪽 전용 공간 하단에 고정된다. 본문은 최대1100px를 유지한다. 좁은 창에서는 하단 요약으로 바뀌며 페이지 끝의 조작 공간을 확보한다.
- 카드·입력폼·단계·모델 선택·영구삭제 동작은 변경하지 않았다. 기존 주소 `http://127.0.0.1:5173`을 사용한다.
- 실제 긴 이력을 펼친 상태의 휠·접힘·마지막 버튼 접근 등5개 화면폭45항목을 확인했다. 이번 확인은 읽기/화면 전환만이며 실제 생성·프로젝트 삭제는 하지 않았다.

## 최신 화면 보정
- 넓은 모니터에서도 목록·제작 본문은 최대1100px로 제한된다. 기존 제작 단계·입력폼·카드 배치는 유지한다.

## 최신 사용법 — 독립 프로젝트 목록과 영구 삭제

1. **http://127.0.0.1:5173** 을 열면 전체 폭 프로젝트 목록이 나온다. 제목 검색, 단계/상태·최근 수정·장수와 각 행의 **열기 / 영구 삭제**를 사용한다. 기존 `?project=UUID` 주소는 해당 제작 화면으로 직접 연결된다.
2. 새 작업은 **새 프로젝트**, 진행하던 작업은 **열기**를 누른다. 제작 화면에서 **프로젝트 목록**을 누르면 관리 페이지로 돌아간다. 이동은 실행 중 제작을 취소/재실행하지 않는다.
3. **영구 삭제**를 누르면 대상 이름과 복구 불가 안내가 나온다. **영구 삭제 확인**을 눌러야 앱의 DB 기록·이미지·ZIP을 제거한다. **취소**는 삭제하지 않는다. 진행 중인 작업은 먼저 별도로 취소/종료해야 하며 삭제가 자동 취소하지 않는다.
4. 파일 잠금 등으로 ‘삭제 미완료’이면 파일 사용을 마치고 해당 삭제 요청을 다시 확인한다. 부분 실패는 성공으로 표시하지 않는다. 다운로드 폴더의 사본이나 제공자 전역 캐시는 이 앱의 삭제 범위가 아니다.
5. 하단의 작은 **남은 사용량** 요약은 모든 화면에 유지된다. Claude/Gemini 주요 게이지와%가 항상 보이고, 나머지 한도·조회 시각·상세는 **사용량 상세**에서 펼친다. 이미지 전용 한도 미제공은 그대로 구분한다.

검증: 실제 합성 PNG·ZIP·DB 삭제 및 브라우저31항목, 전체 로컬407pass/2skip·화면77pass, 실제 원본7개 목록·제작복원·삭제 확인 취소. 기존 사용자 프로젝트는 삭제하지 않았다. 현재 앱은 켜 두었으며 아래 과거 사이드바 설명/검사 수보다 이 절과 루트 현재상태가 우선한다.

## 최신 안내 — 프로젝트 목록·모델·사용량

- 접속: **http://127.0.0.1:5173**. 새 빌드 적용 후 실제 기존 프로젝트7개와 모델13개를 확인했다. 이미 켜 두었으므로 중복 실행하지 않는다.
- 왼쪽 **프로젝트 목록**에서 이전 작업을 선택한다. 검색으로 주제를 찾고 브라우저 뒤로/앞으로 이동할 수 있다. 이동만으로 진행 중 작업이 취소되거나 재실행되지는 않는다.
- 상단 **Claude 모델**은 해당 계정/SDK가 반환한 목록이다. 선택은 프로젝트별로 저장되고 다음 실행부터 적용된다. 실행 중 변경해도 현재 실행의 모델은 바꾸지 않는다. SDK 기본 모델은 명시 모델 미지정을 뜻하며 다른 API 과금 경로가 아니다.
- 왼쪽 하단(좁은 화면에서는 화면 하단)에 **남은 사용량**이 항상 보인다. Claude 구독과 Gemini·Antigravity의 실제 한도별 게이지/%·초기화/확인 시각을 표시한다. 보이는 탭에서60초 주기와 수동 버튼으로 조회하며, 조회는 조사·이미지 생성을 시작하지 않는다. 실패/오래된 값은 따로 표시한다.
- **Gemini 일반 한도는 이미지 생성 잔여량이 아니다.** 이미지 전용 수치는 제공되지 않아 미제공으로 표시한다. Antigravity의 Claude/GPT 그룹은 별도 Claude 구독과 구분하며 접힌 상세에서 확인한다.
- 아직 제출하지 않은 주제·기간·후보 선택·질문·수정 초안은 프로젝트를 오가는 동안 보존된다. **페이지 새로고침/탭 닫기 전에는 필요한 입력을 제출해야 한다.** 제출된 프로젝트/결과/모델 설정은 DB에 남는다.
- 이번 검증: 집중 통합157pass, 최종 화면67pass, 타입검사·빌드exit0, 격리 실제HTTP·브라우저17항목, 원본 앱 조회/초안 이동/실제 계정 잔여량 확인. 모델·검색·이미지 생성 프롬프트는 이번에 보내지 않았다. 사용자 데이터12개 기존 테이블 행과25개 자산 해시를 보존했다.
- 아래 절의 PID·검사 수·카드 제작 상태는 과거 단계 기록이다. 현재 작업/알려진 한계는 루트 `📋 현재상태.md`의 최신 완료 절을 우선한다.

## 최신 안내 — 웹 연결·진행 표시 보완 후

- 접속: **http://127.0.0.1:5173**. 이번 인계에서 실제 HTTP200과 기존 데이터 복원을 확인했다. 켜 둔 앱을 중복 실행하지 않는다.

- 웹 오른쪽 위 **계정 연결**을 누른다. 기존 로그인은 **연결 확인**, 로그인이 필요한 경우 **Google/agy 로그인 시작** 또는 **Claude Agent SDK 로그인 시작**을 누른다. 공식 브라우저에서 직접 로그인한다. 공식 프로그램이 코드를 요구할 때만 웹에 인증 코드 입력란이 표시되고 전송 즉시 지워진다. 앱은 비밀번호/API 키를 받지 않는다.
- 연결 정보 확인은 계정 메타데이터 확인이며 실제 생성 성공·남은 구독량을 보장하지 않는다. 상태 확인과 로그인은 명시 버튼으로만 시작한다. 실행 중인 제작 작업이 있으면 인증 변경은 기다리게 한다.
- 작업 상태에는 한국어 단계·카드 완료/대기/진행/오류 수·경과시간·최근 실제 활동·별도 서버 조회 시각·시간순 이력이 표시된다. 새로고침 뒤 종료된 작업의 이력도 복원한다. 서버가 응답한다는 이유로 모델 작업이 진행된 것으로 표시하지 않는다.

브라우저에서 **http://127.0.0.1:5173** 을 여세요. dev는 컴파일된 HTTP 서버(8765), 별도 worker, Vite(5173)를 함께 시작합니다. 빌드가 없으면 먼저 build하라는 오류를 냅니다. 포트가 이미 사용 중이면 다른 프로세스를 종료하지 말고 해당 오류를 알려 주세요. 외부 바인딩/터널은 없습니다.

### 빌드된 화면만 서버로 제공하기
개발용 Vite 없이 **http://127.0.0.1:8765** 로 실행할 수도 있습니다. 위 환경 준비와 build 후, 서로 다른 두 PowerShell 창에서 같은 APP 경로·전용 Node 환경으로 실행합니다.

```powershell
# 첫 창: Express + dist/web
& $Node $Npm run start:server
# 둘째 창: 같은 SQLite를 보는 별도 worker
& $Node $Npm run start:worker
```

명령의 실제 대상은 `dist/server/server-main.js`, `dist/server/worker-main.js`입니다. server만 켜면 요청이 저장된 queued 상태에서 기다리고 worker를 켜야 처리합니다. worker도 구독 게이트를 우회하지 않습니다. 두 방식(dev와 개별 실행)을 동시에 켜지 마세요.

## 2. 보관 위치와 종료
- 기본 DB: `02_구현\실행데이터\앱\카드뉴스.sqlite`.
- 프로젝트·시도별 디렉터리/자산은 같은 데이터 폴더 아래 B1/W1이 생성합니다. 자동 삭제·파괴적 재생성·사용자 DB 변경 시험은 하지 않았습니다.
- 창을 다시 열어 같은 APP에서 실행하면 같은 DB를 읽습니다. `?project=<프로젝트 UUID>` 주소로 프로젝트를 복원합니다. 브라우저 세션/CSRF는 재발급되고 프로젝트 원장은 별개로 유지됩니다.
- **이 앱을 실행한 콘솔에서 Ctrl+C**로 종료하세요. dev는 자신이 만든 서버·worker에 IPC 종료를 보내고 종료를 기다립니다. 개별 실행이면 각각의 앱 콘솔에서 Ctrl+C를 누릅니다. 프로세스 이름으로 일괄 종료하거나 Hermes/사용자 브라우저를 종료하지 마세요.
- 검증에 사용한 앱/격리 Chromium은 모두 close/dispose·IPC 종료로 정리했습니다. 테스트 서버를 상시 켜 둔 상태로 인계하지 않습니다.

## 3. 로컬 검증을 다시 실행하기
이 명령은 실제 외부 모델이 아니라 **명시 합성 시험**입니다. UUID별 SQLite/PNG/ZIP/스크린샷을 `실행데이터\I2`에 새로 남깁니다. 초기 화면에서 모의 데이터 배너를 확인하며 정상 앱의 공급자 선택은 바꾸지 않습니다.

```powershell
& $Node '실행데이터\I2\실행.mjs' integration
& $Node '실행데이터\I2\실행.mjs' e2e
& $Node '실행데이터\I2\실행.mjs' focused
& $Node '실행데이터\I2\실행.mjs' frontend
```

`integration`은 읽기 전용인 I1 저장 시험을 제외한 I2 소유 시험만 실행합니다. I1은 기존 `실행데이터\I1\최종검증.json`을 근거로 재사용했고 다시 실행하지 않았습니다. `test:integration -- --checkpoint=question|production|export`도 설치된 wrapper의 실제 필터입니다. 단순히 `npm run test:integration` 전체를 돌리면 I1 시험까지 재실행하므로 이번 재현에는 위 I2 실행기를 사용하세요.
